    Enforcement

    Three checks in one place

    A hook inside the agent evaluates checked tool calls against your policy and blocks recognized violations. If the hook cannot run for a checked tool, the call is blocked instead of allowed.

    • Protected paths

      Writes to configuration, policies, CI, git hooks and agent setup are blocked, and so are writes outside the project directory. No guarantee.

    • Dangerous commands

      Shell commands are checked against your rules before they run, for example force pushes or sudo.

    • Dependencies

      New packages are checked against an allowlist. Installs are blocked until you approve the package.

    Honestly scoped. TollWire’s guardrail recognizes and blocks risky actions before they run; it is defense in depth — a hook, not a sandbox, and does not replace an audit. Run the agent in a container or OS sandbox as well. See “Limits” in the README.

    Flow

    How it works

    Four steps, all on your machine. TollWire sends neither code nor prompts anywhere.

    1. Intercept

      The agent is about to write a file or run a command. The hook receives the call first.

    2. Check

      Paths, commands and dependencies are compared with your policy. Recognized violations are hits.

    3. Decide

      Allowed calls go through; recognized violations are blocked, with the reason shown.

    4. Record

      Each evaluation is written to a hash-chained decision log you can verify. You can switch it off.

    Architecture

    Where TollWire sits

    A PreToolUse hook between the agent and the system. In the enterprise edition the decision log is also forwarded to your SIEM.

    Evidence

    Records, not chat logs

    Every evaluation becomes an event in a hash chain, and the evidence server records changes, reviews, scans and approvals the same way. Event types are mapped to controls as a draft mapping, not audited. TollWire supplies records; it does not certify anything and does not replace an audit.

    Trust

    Check what you install

    Don’t take our word for it. Releases come with checksums and an SBOM, and you can compare the file you downloaded with the copy npm serves.

    npm packages

    @tollwire/guardrail-plugin and @tollwire/evidence-mcp, version 0.1.6. No install scripts; --ignore-scripts is safe.

    GitHub releases

    Each release ships the .tgz packages, SPDX SBOMs and a SHA256SUMS file.

    Read before you run

    A plugin runs code with your user privileges. Read hooks/hooks.json and .mcp.json first and pin the version. See the security notes.

    # in the directory with the downloaded release files sha256sum --check --strict SHA256SUMS # compare with the copy npm serves npm view @tollwire/guardrail-plugin@0.1.6 dist.integrity npm view @tollwire/evidence-mcp@0.1.6 dist.integrity

    The checksum check covers the file you downloaded, not the copy npm serves. The npm value must equal sha512- followed by the base64 SHA-512 of the checked .tgz; details in the README.

    Quick start

    Three commands in Claude Code

    Needs Node.js 22.12 or later and npm. Each plugin installs on its own; you can install only the guardrail.

    /plugin marketplace add TollWire/tollwire /plugin install tollwire-guardrail@tollwire /plugin install tollwire-evidence@tollwire

    The marketplace entry has no integrity digest: verify the release first (above) and read the security notes. Uninstall steps are in the README.
