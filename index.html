    Try it

    Check a tool call, live

    Choose a tool, type a path or command, and see how a TollWire policy would decide — entirely in your browser. This is a simplified reproduction of the rule logic for illustration; the real hook (dist/hookCli.js) is authoritative and checks more.

    Nothing leaves your browser. The checks here are a small illustrative subset (protected paths, writes outside the project, unlisted dependencies, a few risky commands). Full rules and limits are in the README.

    Enforcement

    Three checks in one place

    A hook inside the agent evaluates checked tool calls against your policy and blocks recognized violations. If the hook cannot run for a checked tool, the call is blocked instead of allowed.

    • Protected paths

      Writes to configuration, policies, CI, git hooks and agent setup are blocked, and so are writes outside the project directory. Common detours such as symlink targets are accounted for. No guarantee.

    • Dangerous commands

      Shell commands are checked heuristically against your rules before they run, for example force pushes or sudo. Known bypasses such as loader variables are accounted for.

    • Dependencies

      New packages are checked against an allowlist. The default policy ships an empty allowlist, so installs are blocked until you approve packages.

    Honestly scoped. The check is a blocklist: what no rule recognizes is allowed. It does not analyze script files, make or npm run, and it works only if the agent loads the hook. TollWire is defense in depth, not a sandbox and does not replace an audit. Run the agent in a container or sandbox as well. See “Limits” in the README.

    Supported agents

    One policy engine, several agents. Honest status.

    Claude Code has the plugin hook. The other adapters pass each agent’s pre-execution hook call to the same decision engine, and they are experimental. What happens when a hook fails differs per agent, so the badge tells you whether a block is really enforced.

    • Claude Code

      ENFORCED

      Plugin hook (PreToolUse). Fail-closed for the checked tools: if node or the hook is missing or crashes, the call is blocked.

    • Codex CLI

      ENFORCEDEXPERIMENTAL

      Deny = exit code 2 plus a deny JSON on stdout. Codex asks you to review and trust non-managed hooks (/hooks) before they run.

    • Cursor

      ENFORCEDEXPERIMENTAL

      Fail-closed only if the hook is registered with "failClosed": true. Without it the adapter is DEGRADED: a crash or timeout lets the call through.

    • Copilot CLI

      DEGRADEDEXPERIMENTAL

      An explicit deny blocks (exit 2 plus deny JSON). A hook timeout is fail-open: the tool proceeds. Keep the hook fast.

    • Grok Build

      DEGRADEDEXPERIMENTAL

      Fail-open on crashes, timeouts and malformed output; only an explicit deny blocks. The adapter emits an explicit deny on any error it can catch.

    Status of the adapters: they are tested against each agent’s documented hook format, not against every agent release, and a live run on each installed CLI is still pending. A Gemini CLI adapter is not shipped. Setup per agent: multi-agent guide. Product names are trademarks of their respective owners; TollWire is not affiliated with or endorsed by them.

    Flow

    How it works

    Four steps, all on your machine. TollWire sends neither code nor prompts anywhere.

    1. Intercept

      The agent is about to write a file or run a command. The hook receives the call first.

    2. Check

      Paths, commands and dependencies are compared with your policy. Recognized violations are hits.

    3. Decide

      No hit: exit 0, the call goes through. Hit or error: exit 2, blocked, with the reason on stderr.

    4. Record

      Each evaluation is written to a hash-chained decision log you can verify. You can switch it off.

    Architecture

    Where TollWire sits

    A PreToolUse hook between the agent and the system. In the enterprise edition the decision log is also forwarded to your SIEM.

    Evidence

    Records, not chat logs

    Every evaluation becomes an event in a hash chain, and the evidence server records changes, reviews, scans and approvals the same way. Event types are mapped to controls as a draft mapping, not audited. TollWire supplies records; it does not certify anything and does not replace an audit.

    Trust

    Check what you install

    Don’t take our word for it. Releases come with checksums and an SBOM, and you can compare the file you downloaded with the copy npm serves.

    npm packages

    @tollwire/guardrail-plugin and @tollwire/evidence-mcp, version 0.1.6. No install scripts; --ignore-scripts is safe.

    GitHub releases

    Each release ships the .tgz packages, SPDX SBOMs and a SHA256SUMS file.

    Read before you run

    A plugin runs code with your user privileges. Read hooks/hooks.json and .mcp.json first and pin the version. See the security notes.

    # in the directory with the downloaded release files sha256sum --check --strict SHA256SUMS # compare with the copy npm serves npm view @tollwire/guardrail-plugin@0.1.6 dist.integrity npm view @tollwire/evidence-mcp@0.1.6 dist.integrity

    The checksum check covers the file you downloaded, not the copy npm serves. The npm value must equal sha512- followed by the base64 SHA-512 of the checked .tgz; details in the README.

    Quick start

    Three commands in Claude Code

    Needs Node.js 22.12 or later and npm. Each plugin installs on its own; you can install only the guardrail.

    /plugin marketplace add TollWire/tollwire /plugin install tollwire-guardrail@tollwire /plugin install tollwire-evidence@tollwire

    The marketplace entry has no integrity digest: verify the release first (above) and read the security notes. Uninstall steps are in the README.
